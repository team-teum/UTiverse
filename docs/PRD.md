# UTiverse PRD

- 상태: 초안 v0.1 (요구사항·디자인 원본 대조 전)
- 작성일: 2026-11-16 (Asia/Seoul)
- MVP 목표일: 2026-11-19 (목요일)
- 제품: UTiverse

## 1. 제품 개요

UTiverse는 트랜스젠더와 성별 정체성을 탐색하는 사람들이 서로의 이야기를 읽고 남기며, “나와 비슷한 사람이 여기에도 있구나”라는 연결감을 얻는 커뮤니티 서비스다. 사용자는 공개 실명이나 연락처를 드러내지 않고 아바타와 별칭으로 글과 반응을 주고받는다.

이 문서는 전달받은 우선순위 목록을 기준으로 작성했다. 연결된 Google 문서 세션과 Figma 접근 권한이 없어 링크의 세부 스펙과 화면 구성을 직접 확인하지 못했다. 따라서 화면 세부, 별자리의 의미, 주변 탐색의 정의는 가정으로 표시했다. 원본 확인 후 해당 항목을 확정한다.

## 2. 문제와 목표

### 해결하려는 문제

성별 정체성에 관한 경험을 주변에서 찾기 어렵거나 안전하게 이야기하기 어려운 사람은 자신만 그런 경험을 한다고 느낄 수 있다. UTiverse는 부담이 낮은 글쓰기와 다른 사람의 경험을 읽는 흐름으로 소속감과 공감의 기회를 제공한다.

### MVP 목표

1. 사용자가 짧은 글을 작성하고 다른 사용자의 글을 읽을 수 있다.
2. 사용자는 댓글과 긍정적 반응으로 공감과 지지를 표현할 수 있다.
3. 사용자는 별칭·아바타·별자리 화면을 통해 다른 사람을 알아볼 수 있다.
4. 랜덤 탐색과 (정의가 확정되면) 주변 탐색으로 홈 피드 밖의 글을 발견할 수 있다.
5. 2026-11-19 수업 시간에 실제 브라우저로 핵심 흐름을 시연하고 사용성 피드백을 받을 수 있다.

### 성공 확인 방법

- 시연 계정으로 가입/입장 → 피드 읽기 → 글 작성 → 다른 계정의 댓글·반응 → 프로필 확인 → 탐색 흐름을 끝까지 수행한다.
- 참여자가 안내 없이 글 작성과 반응 버튼을 찾을 수 있는지 관찰한다.
- 소속감과 안전감에 관한 짧은 인터뷰 질문을 기록한다. 민감한 정체성 정보나 실제 경험을 제출하도록 요구하지 않는다.

## 3. 대상 사용자와 제품 원칙

### 대상

- 트랜스젠더 사용자
- 성별 정체성을 탐색하거나 관련 경험을 안전하게 읽고 싶은 사용자
- 수업 시연용 테스트 참여자

### 원칙

- 기본 정체성은 별칭과 아바타다. 법적 이름, 전화번호, 성별 지정, 전환 이력은 수집하지 않는다.
- 사용자 생성 글은 기본적으로 UTiverse 로그인 사용자에게만 노출한다.
- 사용자가 공개 범위와 지역 정보를 선택할 수 있어야 한다. 위치 공유를 필수로 만들지 않는다.
- 별자리나 프로필 표현은 사용자가 선택하거나 이해할 수 있어야 하며, 성별 정체성을 자동 추정하지 않는다.
- 안전 기능은 최소한 자신의 콘텐츠 삭제와 문제 콘텐츠 신고 경로를 제공한다.

## 4. MVP 범위와 우선순위

| 우선순위 | 기능 | 목요일 시연 기준 |
|---|---|---|
| P0 | 글 작성·목록·상세·댓글·반응 | 로그인한 사용자가 글을 저장하고 다른 계정에서 읽기, 댓글, 반응을 할 수 있음 |
| P1 | 타인의 글·별자리·아바타 확인 | 피드 카드에서 작성자 프로필을 열고 별칭, 아바타, 별자리 표현과 글을 볼 수 있음 |
| P2 | 랜덤 탐색 | 현재 사용자가 쓴 글을 제외하고 다른 글을 무작위로 발견할 수 있음 |
| P2 | 주변 탐색 | “주변”의 정의가 지리적 거리로 확정될 경우, 사용자가 직접 선택한 넓은 지역만 필터에 사용. GPS/정밀 좌표 금지 |
| P3 | 계정 생성·로그인 | 익명 Supabase 세션 또는 임시 시연 계정으로 사용자별 작성 권한을 확인. 이메일 등 복구 가능한 가입은 일정 여유가 있을 때 추가 |
| P3 | 튜토리얼·캘린더 화면 | 전달받은 이미지를 정적 화면으로 표시. 실제 튜토리얼 상태 관리나 캘린더 기능은 제외 |

P0 글 작성의 소유자 식별을 위해 최소한의 사용자 세션은 필요하다. 따라서 전체 가입 UX를 후순위로 두더라도 시연에서 계정별 작성 권한을 검증할 수 있는 임시 인증 흐름은 P0 의존성이다. 익명 세션은 계정 복구를 보장하지 않는다. 수업용 임시 계정으로 전환할 경우 계정과 비밀번호를 소스 코드나 커밋에 넣지 않고, 배포 환경에서 별도로 전달한다.

### P0 사용자 흐름

1. 사용자는 익명 입장 또는 준비된 시연 계정으로 접속한다.
2. 별칭과 기본 아바타를 확인하고 홈 피드를 연다.
3. 새 글 화면에서 텍스트를 작성해 게시한다.
4. 피드에서 글을 열어 댓글을 남기고 정해진 긍정 반응 중 하나를 누른다.
5. 다른 사용자의 작성자 카드를 눌러 프로필/별자리 화면을 확인한다.
6. 랜덤 탐색으로 다른 글을 발견한다. 주변 탐색은 opt-in 지역이 설정된 경우만 제공한다.

## 5. 기능 요구사항

### 글

- 로그인 사용자는 빈 글을 게시할 수 없다.
- 글 목록은 최신 글 순으로 표시하고 페이지 단위로 더 불러온다.
- 글 상세에는 별칭, 아바타, 작성 시각, 본문, 댓글 수, 반응 수를 표시한다.
- 작성자는 자신의 글을 삭제할 수 있다. MVP에서 수정은 일정 여유가 있을 때 추가한다.
- 삭제된 글은 일반 사용자에게 내용을 노출하지 않는다. 댓글과 반응의 보존/삭제 방식은 기술 명세를 따른다.

### 댓글

- 로그인 사용자는 글에 댓글을 작성할 수 있다.
- 작성자는 자신의 댓글을 삭제할 수 있다.
- 댓글은 작성 시각 순으로 표시한다. 대댓글은 MVP 범위에서 제외한다.

### 반응

- 반응 종류는 공감·나도 그래·응원 같은 긍정 표현 2~3종을 제안한다. 최종 이름과 아이콘은 Figma 확인 후 확정한다.
- 사용자 한 명은 글 하나에 반응 종류별로 하나만 가질 수 있고, 같은 반응을 다시 누르면 취소된다.
- 비추천/공개 점수/랭킹은 제공하지 않는다.

### 프로필·별자리·아바타

- 별칭과 기본 아바타를 표시한다. 사용자의 실명·이메일·인증 정보는 프로필 화면에 노출하지 않는다.
- 다른 사람의 글과 프로필을 열 수 있다.
- “별자리”가 어떤 데이터와 규칙으로 생성되는지는 원본 디자인·스펙 확인이 필요하다. 확인 전에는 선택한 별자리 장식 또는 고정된 시각 컴포넌트로 구현하며 정체성·활동을 추론해 생성하지 않는다.

### 탐색

- 랜덤 탐색은 피드의 최근 공개 가능 글 중 한 건을 무작위로 가져온다. 같은 결과가 이어지면 새로고침/다음 탐색으로 바꿀 수 있다.
- “주변 탐색”이 실제 지역 기반 탐색을 의미하는지 원본 확인이 필요하다. 지리 기반으로 확정될 때만 사용자가 직접 선택한 시·도 등 넓은 지역을 이용한다. 브라우저 위치 권한, 위도/경도, 거리 계산, 실시간 위치 수집은 하지 않는다.
- 선택한 지역이 없는 사용자는 주변 피드를 볼 수 없고 설정 화면에서 지역 선택을 직접 할 수 있다.

### 가입·로그인 및 시연

- 우선 안: 익명 Supabase Auth 세션을 생성해 글 소유자 식별에 사용한다. 사용자가 로그아웃하거나 브라우저 데이터를 지우면 세션 복구가 어려울 수 있음을 UX에서 간결히 알린다.
- 이메일/비밀번호 또는 이메일 OTP 로그인이 일정에 들어오면 추가한다.
- 익명 가입을 쓰는 경우 가입 남용 방지를 검토한다. 공개 서비스 전에는 Turnstile 등 보호와 익명 계정 정리 정책을 정한다.
- 로그인 완성이 어렵다면 개발팀이 생성한 임시 시연 계정으로 대체한다. 계정 목록은 별도 안전한 공유 경로로 전달하고 코드/저장소에 넣지 않는다.

### 튜토리얼·캘린더 정적 화면

- 제공된 이미지가 확보되면 해당 이미지를 모바일 화면에서 읽을 수 있는 크기로 표시한다.
- 이미지 파일이 오기 전까지는 플레이스홀더로 표시하고 추정한 안내 문구나 실제 캘린더 데이터를 만들지 않는다.

## 6. MVP 제외 범위

- 실명 인증, 학교/기관 이메일 인증, 복잡한 계정 복구
- DM, 팔로우, 알림, 검색, 콘텐츠 추천 알고리즘
- 실제 캘린더 일정 생성/동기화
- 정확한 위치 기반 탐색, 지도, 위치 추적
- 이미지 업로드(정적 디자인 에셋 외), 동영상, 음성
- 자동화된 콘텐츠 심사 및 운영자 대시보드
- 성별 정체성, 의료/전환 정보, 법적 정보의 수집

## 7. 안전·운영 요구사항

- 피드와 상세는 인증된 사용자에게만 제공한다.
- 자신의 글과 댓글을 삭제할 수 있다. 모든 신고는 작성자에게 공개되지 않는다.
- 신고는 글 또는 댓글 단위로 저장하고, 초기 시연에서는 팀이 Supabase 대시보드에서 수동 확인한다.
- 지역은 사용자가 명시적으로 선택할 때만 쓰며 계정 프로필에 공개하지 않는다.
- 데모 콘텐츠는 가상 인물과 가상 경험만 사용한다. 실제 참여자의 민감한 경험을 동의 없이 시드 데이터로 사용하지 않는다.
- 민감한 커뮤니티 서비스임을 고려해 외부 광고/행동 추적 분석은 MVP에서 넣지 않는다.

## 8. 완료 기준

- 배포된 HTTPS 주소에서 핵심 흐름을 모바일 크기와 데스크톱 브라우저로 확인할 수 있다.
- 최소 두 개의 시연 계정으로 작성자 소유권, 댓글, 반응, 다른 사람 콘텐츠 열람을 확인한다.
- 직접 URL/API 요청을 포함해 다른 사용자의 글을 수정·삭제할 수 없도록 권한이 적용돼 있다.
- 빈 상태, 로딩, 오류, 저장 성공 상태를 사용자에게 표시한다.
- 알려진 제한(익명 세션 복구, 지역 탐색 가정, 정적 캘린더/튜토리얼)을 시연자에게 안내한다.

## 9. 확인이 필요한 결정

1. Google 문서의 실제 기능 요구사항과 예외 흐름은 무엇인가?
2. Figma의 화면 순서, 반응 종류, 프로필 및 별자리 표현, 이미지 에셋은 무엇인가?
3. “주변 탐색”은 실제 위치, 관심사/상태의 유사성, 혹은 다른 의미인가?
4. 글과 댓글의 공개 범위는 전체 로그인 사용자 기준인가, 별도 모임/그룹 기준인가?
5. 사용자 글의 삭제가 댓글까지 함께 삭제해야 하는가?
6. 목요일 시연은 교실 네트워크에서 외부 인터넷 접속이 가능한가?
